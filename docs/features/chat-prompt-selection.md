# 聊天选用个人 Prompt

## 目标与结果

保存的 Prompt 可以在聊天页新会话中选择，第一次发送时关联 Conversation.promptId。续聊沿用关联模板；更换模板需要新建会话。默认知识助手始终可用。

## 文件职责与数据流

- chat/page.tsx 只读取当前用户模板的 id、title 给选择器。
- ChatWorkspace.tsx 在新会话发送 promptId，续聊只传 conversationId。
- validators/chat.ts 校验 id 的格式；prompt.service.ts 检查会话与模板归属。
- api/chat/route.ts 在占用配额之前解析模板，把正文加入系统提示词，同时保留服务端安全约束。
- conversation.service.ts 创建会话时保存关联，读取历史时恢复选择。

浏览器选择 → POST → Session userId → 查询所属会话/Prompt → 读取模板正文 → 关联会话 → 受限 Agent → SSE → 最终回答持久化。

## 关键代码解释

客户端不提交模板正文，因为浏览器数据可篡改。resolveChatPrompt 必须使用 id 和 userId 同时查询；isPublic 不绕过归属。续聊由数据库关联决定模板，篡改为另一个 promptId 会被拒绝。GUEST 无自定义模板权限。不存在、越权或角色不允许的请求在 DeepSeek 调用和配额占用前结束。

## 设计取舍

复用已有可选外键，无需新 migration。模板不是版本快照：修改正文影响后续轮次，旧消息保留；删除模板会解除关联，续聊回到默认助手。需要审计可复现时再引入模板版本，本次不做。系统提示词不是权限边界，数据隔离和调用预算仍由服务器代码强制执行。

公开意向仍为预留属性，界面明确“暂不对外分享”，没有引入市场或跨用户模板访问。

## 面试重点与易错点

解释“可用的资源 id”不等于“有权使用”；会话关联由数据库裁决，不能信任旧页面状态。模板改变回答风格，不改变模型可执行的工具和数据范围。把安全约束写在 prompt 中不能替代 userId 查询条件。

## 验证方法

1. 创建一条要求固定标题的模板，新建会话选择，验证回答与 Conversation.promptId。
2. 刷新、历史续聊，仍沿用模板；现有会话选择器禁用。
3. 提交他人模板、他人会话、Guest 模板请求，均拒绝且不扣配额。
4. 修改模板后续聊使用新正文；删除模板后刷新为默认，旧回答保留。
5. 未选择模板的聊天行为保持原状。

## 后续改进

模板快照、变量和版本历史可以独立设计；公开市场继续延期。
