# 固定人工演示数据

## 目标与结果

准备一套可重复使用的本地账号、知识和模板，让现场演示无需临时编造问题。用户明确不需要 PPT 和录屏，本功能只准备数据与人工步骤。

## 相关文件职责与数据流

scripts/prepare-demo.mjs 调用本地注册接口生成随机密码账号，再向本地 Compose 数据库插入固定知识和模板；.env.acceptance-demo.json 保存本地凭据且被 Git 忽略。docs/acceptance/manual-demo.md 提供问题、预期事实、步骤和备用方式。

脚本 → localhost 注册（bcrypt 哈希）→ 精确 userId → 本地 PostgreSQL 数据 → 登录后的页面与 Agent 检索。演示管理员用于六页展示，第二个 USER 用于证明隔离。

## 关键代码与设计取舍

只连接固定 localhost 和 Compose，不读取 Neon URL。对 userId 与标题使用 NOT EXISTS 防止重复插入，账号存在但本地密码文件缺失时停止，避免重置已有密码。这个幂等策略保留用户后来编辑过的同名内容；它不负责把数据库强制恢复成初始快照。

创建独立强密码演示账号，避免使用公开弱密码 seed；重复运行不修改账号权限或密码。不自动生成聊天回答，现场请求真实模型，建议提前人工完成并保留一条成功会话作备用。

## 面试重点与易错点

解释幂等与覆盖的区别，说明账号、模板和知识按 userId 关联。展示 Compose 数据不代表 Neon 已导入。Git 忽略只防误提交，不是文件加密；投屏时不要打开密码文件。

## 验证方法

本轮已重复执行准备脚本并通过真实 Chrome 登录：ADMIN 可见三条星河知识，USER 可见一条独立笔记且看不到管理员条目。注册密码走正常 bcrypt 流程；凭据文件用 git check-ignore 确认忽略。

## 后续改进

若要在公网使用，应通过明确的账号和数据导入流程准备，不能把本地脚本接入生产启动。大量数据或并发导入时再使用唯一约束与事务化导入任务。
